    Verifikasi Security Rules

    Jalankan di Rules Playground setelah memublikasikan firestore.rules terbaru. Hasil berikut adalah skenario uji yang divalidasi oleh aturan keamanan:

    Siapkan profil A (pemilik), B (anggota), C (bukan anggota), D (admin). Proyek P memuat A dan B. Gunakan data valid sebagai dasar; ubah satu field per percobaan. Timestamp create/update harus sama dengan waktu request.

    1. Tanpa autentikasi: get users/A, get projects/P, create tugas/proyek → ditolak.
    2. C membaca projects/P atau tugas P → ditolak; A dan B membaca → diizinkan.
    3. Registrasi profil milik sendiri dengan role admin/manager atau isPlaceholder true → ditolak.
    4. B mengubah role sendiri dari member menjadi admin → ditolak.
    5. Non-owner B menghapus projects/P → ditolak; A menghapus proyek → diizinkan.
    6. C membuat tugas di proyek P tempat ia bukan anggota → ditolak.
    7. A/B membuat tugas dengan status/prioritas tidak dikenal → ditolak.
    8. Judul tugas kosong atau melebihi 120 karakter → ditolak.
    9. Tenggat proyek sebelum tanggal mulai → ditolak.
    10. Anggota non-owner B mengubah nama, deskripsi, atau memberIds pada projects/P → ditolak.
    11. Field immutable (ownerId, projectId, code, createdAt) tidak dapat diubah → ditolak.
    12. Komentar tidak dapat diubah, hanya dapat dihapus oleh penulisnya atau pemilik proyek → diizinkan sesuai otorisasi, update ditolak.
    13. Aktivitas audit bersifat immutable dan append-only → update/delete dari klien ditolak.
    14. D menghapus profil akun nyata (isPlaceholder false) → ditolak. D menghapus profil demo ber-ID placeholder_* → diizinkan.
    15. Cascade delete oleh pemilik menghapus dokumen terkait dalam batch $\le 5$ dokumen tanpa melebihi budget Rules.
    16. Query projects/tasks tanpa filter memberIds array-contains oleh non-admin → ditolak; dengan filter keanggotaan dan limit $\le 24$ (proyek) / $\le 150$ (tugas) → diizinkan.

    Counter tidak dapat diubah oleh siapa pun lewat klien pada Increment 1, termasuk owner/admin. Verifikasi update taskTotal/taskDone ditolak. Pemeriksaan tanggal di Rules saat ini membatasi format, rentang bulan/hari, dan urutan tanggal; validitas kalender penuh diperiksa validator klien.

    Uji lintas-dokumen tugas, komentar immutable, activity immutable, serta cascade akan ditambahkan bersama Rules fiturnya pada increment selanjutnya. Playground hanya menguji dokumen; uji query dari aplikasi atau Emulator Suite.
